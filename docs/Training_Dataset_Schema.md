# Training & Evaluation Dataset

ClauseLens does not train a large language model. The dataset exists to **evaluate** (and later train small components such as the document classifier) against documents whose correct answers are known.

Schemas: [`document_metadata.schema.json`](../data/schemas/document_metadata.schema.json) (one entry per document) · [`normalized_document.schema.json`](../data/schemas/normalized_document.schema.json) (annotations) · [`legal_fact.schema.json`](../data/schemas/legal_fact.schema.json) (fact labels)

## 1. Four separate kinds of data

| Kind | What | Used for | Can contain user uploads? |
|---|---|---|---|
| **User documents** | Files people upload to use the app | Only that user's search, Q&A, summaries | — |
| **Training dataset** | Licensed / synthetic documents with labels | Training small models (classifier, extractors) | **Only with explicit, recorded consent** |
| **Evaluation dataset** | Licensed / synthetic documents with labels | Measuring quality before each release | Same rule |
| **Retrieval knowledge base** | Reference material (e.g. glossary of legal terms) | Explaining terms | No |

User documents are **never** copied into any dataset automatically. See [Data_Governance.md](Data_Governance.md).

## 2. Organisation

```text
dataset/
├── government/   notifications/ circulars/ orders/ gazettes/ public_notices/ guidelines/
├── contracts/    employment/ nda/ lease/ service/ vendor/ terms_conditions/
├── court/        judgments/ orders/ petitions/ affidavits/ notices/
├── company/      policies/ agreements/ resolutions/ reports/
├── public/       notices/ advisories/ announcements/
├── property/     lease/ sale/ registration/ notices/
└── metadata/     evaluation_index.json (+ train/validation/test indexes)
```

Each document: `<folder>/<DOC_ID>.<ext>` plus its annotation `<folder>/<DOC_ID>.json` (a normalized document). The folders are a storage convenience; the authoritative label is `document_type` in the metadata.

The 4 fictional sample PDFs in `samples/` are registered in [`dataset/metadata/evaluation_index.json`](../dataset/metadata/evaluation_index.json) as the first evaluation documents.

## 3. Metadata (per document)

Required: `document_id` (`DOC_00001`), `category`, `document_type` (taxonomy id), `language`, `format`, `is_scanned`, `page_count`, `split`, `source`, `license`, `collection_method`, `permission_status`, `privacy_status`.

Useful: `subcategory`, `sha256`, `near_duplicate_group`, `ocr_required`, `country`, `jurisdiction`, `date`, `document_version`, `has_tables`, `has_signature`, `has_annexure`, `contains_handwriting`, `contains_images`, `contains_stamps`, `contains_headers`, `contains_footers`, `source_type`, `copyright_status`, `annotations_path`.

```json
{
  "document_id": "DOC_00001",
  "category": "employment",
  "subcategory": "employment",
  "document_type": "employment.employment_agreement",
  "language": "en",
  "format": "pdf",
  "is_scanned": false,
  "page_count": 10,
  "split": "evaluation",
  "source": "Generated by backend/scripts/make_sample_pdf.py (fictional content)",
  "license": "project-owned",
  "collection_method": "created",
  "permission_status": "owned",
  "privacy_status": "synthetic"
}
```

## 4. Rights, licensing and privacy (entry rules)

A document may enter the dataset only if **all** hold:

1. `license` / `permission_status` show we may use it (owned, licensed, public domain, government open data licence, or recorded consent). **No indiscriminate scraping; no private or copyrighted documents without permission.**
2. `privacy_status` is `synthetic`, `no_personal_data` or `anonymised`. Documents with real personal data are anonymised first (names, addresses, ID numbers, phone numbers, signatures, photos).
3. `source` and `collection_method` are filled in so the origin can be audited.

## 5. Annotation format

Annotations are normalized documents ([examples](../data/examples)). Labels:

| Task | Label | Where |
|---|---|---|
| Classification | category, document type | `document.classification` (`method: "user"`, `status: "user_verified"`) |
| Structure | sections, section roles, clause numbers, page ranges | `sections[]` |
| Concept extraction | concept id + value + normalized value | `facts[]` |
| Source evidence | page, clause, exact text, `char_start`/`char_end` | `facts[].evidence` |
| OCR | per-page OCR flag, engine, confidence; `is_scanned`, `ocr_required` | `pages[].ocr`, metadata |

Evidence must be exact: `pages[p].text[char_start:char_end] == source_text` (checked automatically).

## 6. Evaluation examples

| Type | Input | Expected |
|---|---|---|
| Classification | document | category, document type |
| Concept extraction | clause | concept, value, source (page + clause) |
| Search | question | relevant page(s) and clause(s) |
| Q&A | question | answer (or "not found"), source |
| Citation | answer | page → clause → exact source text exists |

Today's automated set: `backend/tests/evaluation_cases.py` (25 cases across a contract, a government notice and an Act/Rules document, including typos, "notice period"-type searches, missing information and questions about the tool). Run it against a live server with `uv run python -m scripts.evaluate`.

## 7. Splits and leakage

- Splits: `train`, `validation`, `test` (models) and `evaluation` (release gate).
- A document and all its near-duplicates (same template, versions, corrigenda, translations, a corrected copy) share one `near_duplicate_group` and **one split**.
- Detect duplicates by `sha256` (exact) and text similarity (e.g. MinHash over normalized text, threshold 0.8) before assigning splits. The test suite rejects the same file appearing in two splits.
- Split by **group**, and where possible by issuer/template, so the test set measures generalisation rather than memorised templates.

## 8. Quality control and metrics

- Two annotators per document for the test/evaluation splits; disagreements resolved by a reviewer; agreement reported (Cohen's κ for types, span F1 for evidence).
- Metrics per release:
  - **Classification:** type accuracy, category accuracy, macro-F1, calibration (ECE).
  - **Extraction:** concept precision / recall / F1; date and amount exact-match accuracy.
  - **Retrieval:** Recall@K, Precision@K, MRR, relevant-page accuracy.
  - **Q&A:** groundedness, citation correctness, source coverage, unsupported-claim rate (target 0), correct "not found" rate.
  - **OCR:** character error rate, page preservation, table extraction quality.
